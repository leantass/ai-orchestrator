# JEFE Master Roadmap V1

Este documento guarda el mapa maestro del producto JEFE dentro del repo. JEFE no debe entenderse solo como generador de demos locales: el producto final debe crear proyectos nuevos, continuar proyectos existentes, auditar, terminar, refactorizar, agregar modulos, preparar releases, medir negocio y guardar memoria validada.

## FASE A - Demo local controlada

Estado: partial / implemented.

Incluye brief intake, project type registry, target platform detector, capability matrix, 10 reportes, primera version local mock, abrir app demo, abrir carpeta, copiar rutas, arquitectura prevista visible y niveles L0/L1.

## FASE B - Input assets y materiales de marca

Estado: planned.

Debe contemplar logos, imagenes, PDFs, screenshots, referencias visuales, colores de marca, notas de estilo, copia segura de assets al run, copia segura de assets al proyecto y uso simple de logo/colores. En V1 no hay OCR ni analisis avanzado; el analisis visual avanzado queda para fases futuras.

## FASE C - Modos de proyecto

Estado: planned.

JEFE debe soportar crear proyecto nuevo, continuar proyecto existente, importar/auditar proyecto existente, terminar proyecto incompleto, refactorizar proyecto, agregar modulos, preparar deploy, mejorar monetizacion y cerrar producto si no conviene.

## FASE D - Contexto y decision de inteligencia

Estado: planned.

JEFE debe decidir si alcanza con brief actual, assets cargados, memoria local validada, docs del proyecto, registry interno, scans seguros del repo, patrones validados y decisiones canonicas previas. Si no alcanza, debe decidir si pregunta al usuario, usa Hermes / Scout, usa OpenAI API, usa investigacion externa futura o bloquea por falta de informacion.

Toda escalada debe registrar motivo, informacion faltante, riesgo, costo estimado, aprobacion requerida y proxima accion permitida.

## FASE E - Codex Builder Loop

Estado: planned.

Debe dividir trabajo, crear tareas, pasar prompts controlados a Codex, construir, modificar, documentar, revisar contra contrato, devolver errores, repetir y registrar aprendizajes validados.

## FASE F - Assets y datos

Estado: planned.

Debe generar assets simples, estructura de assets, logos placeholder, iconos, imagenes mock, textos/copies, modelos de datos, schemas, seeds, fixtures, mock data, migraciones futuras, DB local/dev y DB productiva solo en fases avanzadas con aprobacion.

## FASE G - QA y testing

Estado: planned.

Debe contemplar Vitest, MSW, tests de logica, tests de servicios, tests de componentes, Playwright, flujos reales, responsive, accesibilidad, evidencia visual y regresiones.

## FASE H - Seguridad, calidad y rendimiento

Estado: planned.

Debe contemplar Gitleaks, Semgrep, Trivy, axe, Lighthouse, revision de secretos, revision de dependencias, performance budgets y controles de seguridad por tipo de proyecto.

## FASE I - Evaluacion IA

Estado: planned.

Debe contemplar Promptfoo, evaluacion de prompts, evaluacion de agentes, regresiones, seguridad de respuestas, costos/tokens y calidad de outputs.

## FASE J - Release

Estado: planned.

Debe contemplar staging, pruebas post-deploy, produccion, rollback, monitoreo y aprobacion explicita antes de publicar.

## FASE K - Analitica y monetizacion

Estado: planned.

Debe contemplar adquisicion, activacion, retencion, conversion, costos, tokens, anuncios, suscripciones, ingresos, rentabilidad y decision de escalar, cambiar monetizacion o cerrar producto.

## FASE L - Memoria validada

Estado: planned.

Debe guardar decisiones, errores resueltos, patrones reutilizables y aprendizajes solo despues de validacion. No debe guardar basura experimental como memoria canonica.
