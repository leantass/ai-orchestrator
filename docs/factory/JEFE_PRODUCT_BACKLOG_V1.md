# JEFE Product Backlog V1

## 1. Universal project generation

Estado: partial / implemented L0-L1. Objetivo: crear proyectos nuevos desde brief y primera version local mock. Entregables: registry, detector, capability matrix, 10 reportes, mock app. Riesgos: deteccion heuristica imperfecta. Dependencias: smokes. Proximo paso: input assets.

## 2. Input assets and brand materials

Estado: planned. Objetivo: aceptar logos, imagenes, PDFs, screenshots, referencias visuales, colores y notas. Entregables: upload seguro, copia al run, copia al proyecto, uso basico de marca. Riesgos: archivos grandes, formatos inseguros, OCR no soportado. Dependencias: policy de rutas. Proximo paso: contrato de assets.

## 3. Existing project continuation

Estado: planned. Objetivo: continuar proyecto existente sin romperlo. Entregables: scan seguro, deteccion de stack, plan de continuacion. Riesgos: sobrescritura, cambios sin aprobacion. Dependencias: project modes. Proximo paso: modo continuar.

## 4. Local memory and context retrieval

Estado: planned. Objetivo: recuperar memoria local validada y docs canonicos. Entregables: memory index, decision records, retrieval seguro. Riesgos: guardar basura experimental. Dependencias: governance. Proximo paso: esquema de memoria validada.

## 5. OpenAI / Hermes / Scout escalation policy

Estado: planned. Objetivo: decidir memoria local vs usuario vs Hermes / Scout vs OpenAI API. Entregables: decision object, approvals, cost control. Riesgos: costo, red, informacion externa incorrecta. Dependencias: policy gates. Proximo paso: evaluador de suficiencia de contexto.

## 6. Codex build orchestration

Estado: planned. Objetivo: orquestar Codex para construir, modificar, probar tecnicamente y documentar. Entregables: tareas controladas, prompts, revision contra contrato. Riesgos: cambios amplios, loops sin control. Dependencias: approvals. Proximo paso: task contract.

## 7. Asset generation

Estado: planned. Objetivo: crear assets simples y placeholders. Entregables: logo placeholder, iconos, imagenes mock, paletas, copies. Riesgos: assets genericos o derechos de uso. Dependencias: input assets. Proximo paso: asset roadmap.

## 8. Database / schema generation

Estado: planned. Objetivo: crear modelos de datos, schemas, seeds, fixtures y DB roadmap. Entregables: data model, schema plan, mock data, migrations futuras. Riesgos: DB productiva temprana, datos personales reales. Dependencias: delivery levels. Proximo paso: reglas L1-L9 de DB.

## 9. Testing pipeline

Estado: planned. Objetivo: Vitest, MSW, tests de logica, servicios y componentes. Entregables: plan QA y configs futuras. Riesgos: falsa confianza sin E2E. Dependencias: scaffold tecnico. Proximo paso: definir L4.

## 10. Security / quality / performance pipeline

Estado: planned. Objetivo: Gitleaks, Semgrep, Trivy, axe, Lighthouse y performance budgets. Entregables: checks futuros y reportes. Riesgos: secretos, vulnerabilidades, baja performance. Dependencias: QA pipeline. Proximo paso: matriz por tipo de proyecto.

## 11. Promptfoo / AI evaluation

Estado: planned. Objetivo: evaluar prompts, agentes, regresiones, seguridad y calidad IA. Entregables: eval plan, datasets, cost tracking. Riesgos: outputs inseguros, regresiones. Dependencias: IA real aprobada. Proximo paso: policy L7.

## 12. Staging and production release

Estado: planned. Objetivo: preparar staging, pruebas post-deploy, produccion y rollback. Entregables: release checklist. Riesgos: publicacion prematura. Dependencias: QA, seguridad, approvals. Proximo paso: L8/L9 gates.

## 13. Analytics and monetization loop

Estado: planned. Objetivo: medir adquisicion, activacion, retencion, conversion, costos, tokens, anuncios, suscripciones e ingresos. Entregables: metric model y decisiones build/scale/kill. Riesgos: optimizar sin datos suficientes. Dependencias: release. Proximo paso: metric contract.

## 14. Memory learning system

Estado: planned. Objetivo: guardar memoria validada. Entregables: decisions, errores resueltos, patrones reutilizables. Riesgos: memoria contaminada. Dependencias: validation gates. Proximo paso: canonical memory rules.

## 15. UI / UX for non-technical users

Estado: partial. Objetivo: UI clara para intake, primera version y roadmap. Entregables: cards de entrega, arquitectura prevista, roadmap JEFE. Riesgos: sobrecargar UI. Dependencias: contrato de estados. Proximo paso: UX de modos.

## 16. Governance, approvals and cost control

Estado: planned. Objetivo: approvals, policy gates, costo estimado y acciones permitidas. Entregables: approval records, cost risk, audit trail. Riesgos: ejecucion real sin permiso. Dependencias: escalation policy. Proximo paso: decision schema.

## 17. Project import / audit

Estado: planned. Objetivo: auditar proyecto existente antes de cambiar. Entregables: diagnostico, riesgos, plan, QA recomendado. Riesgos: leer demasiado o tocar sin permiso. Dependencias: scan seguro. Proximo paso: audit mode.

## 18. Project completion mode

Estado: planned. Objetivo: terminar proyecto incompleto. Entregables: gap analysis, backlog faltante, criterios de aceptacion, readiness. Riesgos: definir terminado sin contrato. Dependencias: project audit. Proximo paso: completion checklist.

## 19. Project shutdown / kill decision

Estado: planned. Objetivo: decidir cerrar producto si no conviene. Entregables: score, riesgos, monetizacion, recomendacion. Riesgos: decision sin research suficiente. Dependencias: analytics y Scout. Proximo paso: kill criteria.

## 20. Packaging and distribution of JEFE itself

Estado: planned. Objetivo: empaquetar y distribuir JEFE. Entregables: installer, updates, seguridad local. Riesgos: credenciales, permisos, updates inseguros. Dependencias: producto estable. Proximo paso: packaging plan.
